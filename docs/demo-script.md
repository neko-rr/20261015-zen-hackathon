# 審査用デモ確認シート

> 審査方式は [レギュレーション要約](google-cloud-japan-ai-hackathon-vol5-regulation-summary.md) から転記。提出審査はリモート。登壇用の台本ではない。

## 審査方式（要約から転記）

| 項目 | 内容 |
|------|------|
| 方式 | 提出物とデプロイ URL を審査員がリモートで確認。ネイティブのみの場合はデモ動画中心 |
| 時間 | デモ動画は約3分。最終ピッチ（2026-12-01）の持ち時間は未確認 |
| プレゼン | 提出時の登壇は記載なし。ファイナリストは最終ピッチがある |
| 提出物 | GitHub 連携、デプロイ URL、説明文、アーキテクチャ図、YouTube デモ動画 |

## 審査前チェック

- [ ] デプロイ URL が審査環境で開ける
- [ ] 動作確認の方法に、審査用 `reviewer` でログインしてサンプル写真を開く、と書いてある。メール／Google ログインは無い
- [ ] ソーシャルログイン、メール受信必須のログインになっていない
- [ ] 共有デモアカウントや、審査員同士で履歴が混ざる設計になっていない
- [ ] 約3分の動画で、対象ユーザー・課題・エージェントの動作が分かる
- [ ] 主要機能がモックではない
- [ ] 2026-12-01 まで URL とデフォルトブランチを維持できる

## 操作フロー（審査員視点）

| 順 | 操作 | 見せたいポイント | 完了 |
|----|------|----------------|------|
| 1 | URL を開くとログイン画面だけが出る。審査用 reviewer でログインし、右上にログイン中の名前が出てから作業する。写真が無いときは「座っている人」と入れるか、「声で言う」で話す。人形の上の候補か「次の候補」で切り替える。「やめる」で消す。またはサンプル写真を開く。カメラなら枠に頭から足を入れる | メールなし。人の区別はユーザー名。審査用は共有。自分のアカウントは分離。言葉は最大3候補で、立ち姿の人形の角度だけ。小さい人は注意が出る。写真ならファイル内の作者名と著作権表示。無ければ未確認。同じ画像の掲載ページがあれば出す。権利者の断定ではない | [ ] |
| 2 | 描くときは右上の「出典をしまう」で右側を横へ収納し、写真を大きく見る。戻すときは右端の「出典」。1〜4枚を並べる。増えたマスは別角度の3D。各マスで元画像／マスク／骨格／筋肉／3Dを選び、3Dは正面・斜め・横・後ろを個別に変える。複数人は同時に色分けされる。層で人を選ぶと、その人だけ頭身・体つき・手・左右反転・ねじれが変わる。3D の体は X Bot と人物を選べ、頭身とポーズはその体に乗る。ドラッグ回転と関節ドラッグ（肘と膝は逆に折れない）。操作は体・線・向き。目盛りと重心線はオンとオフ。透視はオフ、アイレベル、1点、2点。線はドラッグ。写真を反転すると補助線も一緒に反転する。色を抜くと明暗だけになる。骨格では濃さを下げて写真と見比べる。青は補完 | 写真を先に出し、人形が出てから呼び方が埋まる。重なりが分かる。絵は生成しない | [ ] |
| 3 | 物体の呼び方（見た目。確かな公開人物だけ名前）を選び、分かるときだけ題名か作者を入れて調べる | 見た目だけではウェブ検索しない。題名か作者があるとき似た資料。権利はページの文だけ。無ければ未確認。当たればジャパンサーチの権利コード。西暦があれば新しい年から満了日 | [ ] |
