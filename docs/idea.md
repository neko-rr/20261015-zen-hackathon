## 一言ピッチ

絵描きが写真資料を物体の層と関節に分け、選んだ部分を出典付きで調べ、引用に使える履歴を残せる。

## MVP（Must）

- ユーザー名とパスワードでアカウントを作る。メール／Google ログインは不要。同じユーザー名は登録できない。パスワードは他の人と同じでもよい。はじめて使うときは、空いているユーザー名をランダムに入れられる。言語とテーマ色はそのアカウントに保存する。未ログインでは作業画面を出さず、ログイン中のユーザー名を出す。審査用アカウントは `reviewer`（審査員の共有）。ログインしない試用は無い
- 写真を1枚アップロードできる。サンプル写真は読み取り専用カタログから選び、解析結果はそのセッション内だけに残る
- 物体ごとに分け、レイヤーの表示を切り替えられる（元画像／マスク／骨格／筋肉／回転 3D）
- 人、または動物の主対象に、関節が分かる表示を重ねる（人は MediaPipe の姿勢と手。最大4人を同時に人形にする。選んだ人だけ頭身・体つき・手・曲げ・ねじれを替える。枠に張り付いた節や胴より長すぎる節は落とし、写っていない節は補完し色分け）
- 物体の呼び方は、写真から読める範囲にする（例: 成人の女性、白いシャツ。場所や道具は別物体）。公開の人物だと分かるときだけ名前を足す。読める題名だけ作品名として残す。見た目の呼び方だけでは著作物を検索しない。題名か作者が分かるときだけ調べ、出典 URL 付きで短く返す。同じ写真の掲載ページは Cloud Vision の Web Detection で残す。権利者の断定ではない
- 出典ごとに、ライセンス・作成時期・著作権の記載を抜き、履歴に残す。ページに無い項目は「未確認」。西暦が書いてあれば、今年以前でいちばん新しい年から70年後の満了日を残す。年が無ければ未確認。題名か作者がジャパンサーチに当たった資料は、API の権利コードだけを足す。アップロードした写真の権利者ではない。写真ファイル内の作者名・著作権表示・画像 ID・クレジット・C2PA の有無は、書いてあるときだけ残す
- 写真・履歴はセッションの `owner_id` 単位で隔離する。ユーザー間で共有しない
- 手元資料を `/library` に登録できる（自作／他者の二領域）。チャットは資料庫と、その人の作業メモ・記録、同じ写真の直近の会話を繋ぐ。出典検索は、調べるボタンと、開いた資料への指定だけ

## 技術スタック

- 実行プロダクト: Cloud Run
- AI: Gemini（写真からの呼び方、検索の出典 URL、言葉から既存関節の角度、自信が低いときの体の向きと、肘が反対の肩に付いたときの手足の状態。座標には使わない）。Cloud Speech-to-Text（ポーズの言葉をマイクから文字にする。音声はサーバーだけが送る）。Cloud Vision の Web Detection（この画像の掲載ページ。権利者の断定には使わない）。MediaPipe（人の輪郭マスク、姿勢、手・CPU）。Jev（チャットで、引用がライセンス等を書いているか）
- 画面: 元画像／マスク／骨格／筋肉／Three.js のデッサン人形（回転と関節の曲げ）
- 認証（ハッカソン）: ユーザー名とパスワード。署名付き Cookie。Firebase Auth / Supabase は使わない。審査用 `reviewer` は共有。それ以外のアカウントは owner が別
- 手元資料: `GCS_BUCKET` があるとき Cloud Storage と Firestore（owner 配下）。`RAG_ENABLED=true` なら人ごとの Gemini API File Search で意味検索し、外れは単語一致。RAG Engine は使わない。キーが無ければ単語一致だけ。自作は `own_work`、他者は `third_party`
- 構成: [architecture.md](architecture.md)。画面と API は別の Cloud Run。Gemini は API だけ
- OSS の表記: 画面 `/licenses`（提出用。製品の Must ではない。依存の自動更新はしない）

## 今回はやらない

- ボタン一つで完成イラストを出すこと（生成AIのポン出し）。資料用の人形の形を写真に合わせるための生成は、ここには含まない
- Kindle 本棚の自動取得（公式 API では蔵書を読めない。非公式取得はしない）
- こちらからの書籍ダウンロード。NotebookLM の非公式クライアント
- 推し活グッズ管理アプリとの統合・SSO（別プロダクト。需要確認後の任意）
- 一般利用者を1つの共有アカウントに入れること。審査用 `reviewer` だけは提出文に書き、審査員が共有する
- カメラ RAW の直接登録（JPEG などに書き出してから）

## 後回し

- 動物の高精度解剖・描いた絵との反映度
- 写真ピクセルを解剖テクスチャに塗り替える生成
- 別端末でも履歴を残す本ログイン（必要になったときだけ IdP を足す）
- 古い `.doc` / `.xls` の完全対応（まずは docx / xlsx）

## 実装済み（Must 外・余力）

MVP の必須ではないが、ローカル／デモ用に入っている。詳細は [architecture.md](architecture.md)。

- 言葉だけで立ち姿の人形を出す。入力のほか、マイクの短い録音を Cloud Speech-to-Text で同じ言葉にする。よく使うポーズはコード内の一覧（約10種、データベースは使わない）。当たればすぐ候補が出る。外れた言葉だけ新しく作る。返すのは既存の関節角度だけで、絵は生成しない
- 写真上の筋肉部位ラベル（姿勢からの近似。医学的正確さは保証しない）
- カメラ撮影時の大きさガイド。小さい人は元画像から切り出して関節を取り直す。遠い人物の注意を画面に出す
- 3D は Mixamo の2体（X Bot と人物）から選べる。ポーズと頭身・体つきは、その体の骨格を曲げる。完成イラストのポン出しではない
- デッサン人形の操作は体・線・向きの3段。最大4枚を並べ、各マスの表示と3Dの視点を個別に見比べる。頭身目盛りと重心線はオン／オフ。写真側にアイレベルと1点・2点透視を出せる。写真ごと左右反転でき、元画像の色を抜いて明暗だけにできる。写真上の人形は濃さを変えられる。左右反転、肩と腰のねじれ。画面上の操作だけで、保存しない
- チャットは資料庫に加え、その人の作業メモ・チャット文言・出典記録と、同じ写真の直近6往復を繋いで答える。メモ作成を頼んだときだけ、選んでいる作業のメモへ足す。メモはウェブに出さない
- 手動の案件は、上げた写真・開いた資料・チャットの文言・出典確認・自由メモの記録。資料庫は人に1つで、案件では仕切らない。作品タグは人が付け、チャットの問い合わせに足す。AI 自動分類はしない
- 同物体の再検索、お気に入り・出典メモ（**セッション内＋制作ログ書き出し**。クラウド永続しない）
- 編集者向け: 危険度目安、引用メモ、チェックリスト、自作／他者比較、制作ログ書き出し
