# 情報源の検証ルール

要約作成時の**必須手順**。省略禁止。

## 情報源の優先順位

| 優先度 | ソース | 用途 |
|--------|--------|------|
| 1 | **参加ラウンドの公式応募要項**（例: `entry-2026-3`） | レギュレーション・当日スケジュール |
| 2 | 大会公式サイト（主催ドメイン） | 概要・ラウンド一覧 |
| 3 | 当日レポート・プレス（公式にリンクされているもの） | 運用実態の補足 |
| 4 | ユーザー提供 PDF | 上記と**照合後のみ**採用 |
| ✕ | 過去大会（前年度）のルール | **引用禁止**（参考程度） |
| ✕ | 記憶・推測・一般的なハッカソン常識 | **記載禁止** |

## レギュレーション要約の鉄則

1. **書いていいのは、取得した原文に明記されている事項のみ**
2. **推測で補完しない** — 不明は `未確認` と書く
3. **過去大会・別ラウンドのルールを混ぜない**
4. **「開発への示唆」「前版の修正点」等の AI 独自解説をレギュレーション要約に入れない**
5. 参加ラウンドが分かっている場合、要約は**そのラウンドにスコープ**する

## PDF の扱い（重要）

PDF は信頼性が低い場合がある。以下を必ず実施:

```
1. PDF からテキスト抽出を試みる
2. 抽出不可（画像PDF）→ PDF 単体を正としない
3. 公式応募要項ページを必ず別途取得して照合
4. PDF と Web で矛盾 → Web（応募要項）を正とし、矛盾を要約に注記
5. PDF の内容だけで要約を完成させない
```

## クロスチェック（Step 2.5）

要約作成前に、以下の**重要項目**を2ソース以上で確認する:

| 項目 | 確認方法 |
|------|---------|
| 審査方式 | 応募要項の「審査方法」セクション |
| 提出物 | 応募要項の「作品レギュレーション」 |
| 当日時刻 | **参加ラウンド**のタイムテーブル |
| 参加費 | 応募要項の「応募」セクション |
| プレゼン要否 | 応募要項 + 当日レポート（あれば） |

**1ソースのみの項目** → 要約に `（単一ソース。要確認）` と付記。

## よくある誤り（禁止パターン）

| 誤り | 正しい対応 |
|------|-----------|
| 2025年ルールを2026年に適用 | 必ず**開催年**の応募要項を取得 |
| PDF だけ読んで要約 | 応募要項 URL を `primary_source` に |
| プレゼン5分・Drive提出を決め打ち | 原文の「審査方法」「提出」を確認 |
| 別ラウンドの申込期間を記載 | 参加ラウンドの情報のみ |
| 一般論をレギュレーション要約に混ぜる | 大会要約とレギュレーション要約を分離 |

## 実例: 全日本AIハッカソン 2026 で起きた誤り

| 誤記 | 正（3rd大阪・公式応募要項） |
|------|---------------------------|
| プレゼン5分・登壇 | プレゼン不要 |
| Google Drive + QR | Web作品URLを事務局に提出 |
| 参加費1,100円 | 無料 |
| Aブロック 9:00集合 | 10:15集合 |

原因: 画像PDFの誤読 + 過去大会ルールの混入 + 応募要項未照合。

## メタデータ（要約ファイル先頭）

レギュレーション要約には必ず:

```yaml
---
primary_source: https://...   # 最優先の公式URL（応募要項等）
secondary_sources:            # 補助ソース（PDF等）
  - url: ...
    note: PDFは応募要項と照合済み
event_round: 3rd              # 参加ラウンド（分かる場合）
event_date: 2026-05-30
fetched_at: 2026-05-29
verified: true                # クロスチェック完了後のみ true
---
```

`verified: true` は Step 4 のチェックリスト全項目クリア後のみ設定。

## Step 4 拡張チェックリスト

- [ ] 各項目に `primary_source` 上の根拠がある
- [ ] 過去大会・別ラウンドの情報が混ざっていない
- [ ] PDF のみに依存している項目がない
- [ ] 審査・提出・スケジュールが応募要項と一致
- [ ] AI が追加した解説（示唆・修正点）がレギュレーション要約に無い
- [ ] 矛盾するソースがある場合、注記している
