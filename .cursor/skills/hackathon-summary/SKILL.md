# ハッカソン要約

ハッカソン公式ページから要約ファイルを作成する。**推測・過去大会ルールの混入を禁止**する。

## トリガー

- ハッカソンURLの共有
- 「要約ファイルを作成」「レギュレーション要約」
- 参加前の情報整理・プロジェクト初期セットアップ

**要約のみ**: 「要約だけ」「フォルダは不要」→ Step 3b スキップ

## ワークフロー

```
Task Progress:
- [ ] Step 1: 情報源の特定と取得
- [ ] Step 2: 情報の抽出・分類
- [ ] Step 2.5: クロスチェック（必須）
- [ ] Step 3a: 要約ファイルの作成
- [ ] Step 3b: プロジェクト構成の作成
- [ ] Step 4: 品質チェック（検証完了まで verified: true にしない）
```

### Step 1: 情報源の特定と取得

**必ず [verification.md](verification.md) の優先順位に従う。**

1. 大会トップページを取得
2. **参加ラウンドの公式応募要項**を特定して取得（最優先）
   - 例: `entry-2026-3`（3rdラウンド）
   - トップページ内リンク、または `entry` / `応募要項` を探索
3. レギュレーション PDF がある場合:
   - テキスト抽出を試みる
   - **画像PDF（抽出不可）→ 応募要項を正とする。PDF単体で要約しない**
4. 過去大会レポートは**補助のみ**。ルールの根拠にしない
5. `fetched_at` を記録

**取得できない場合**: 推測で埋めず `未確認` と明記。

### Step 2: 情報の抽出・分類

- ページに**明記されている事項のみ**抽出
- 空欄・推測値を作らない
- ラウンド制大会: **参加ラウンドにスコープ**（他ラウンドの日程は混ぜない）

| カテゴリ | 抽出内容 |
|---------|---------|
| 基本情報 | イベント名、主催、年次、公式URL |
| 日程 | **参加ラウンド**のタイムテーブル |
| 参加条件 | チーム人数、参加費、必須登録 |
| 作品ルール | 成果物形式、ブラウザ要件等 |
| 審査 | 方式、時間、基準（原文どおり） |
| 提出 | 提出物、提出先、期限 |

### Step 2.5: クロスチェック（必須）

[verification.md](verification.md) の「クロスチェック」表を実施。

```
応募要項 ←→ PDF（あれば）←→ 大会トップ
         ↓
   矛盾があれば応募要項を正とする
         ↓
   矛盾内容を「未確認・矛盾」セクションに記載
```

**以下は必ず応募要項で確認してから記載:**

- 審査方式（プレゼン要否、審査時間）
- 提出物（URL / 資料 / Drive 等）
- 当日スケジュール（集合時刻）
- 参加費

### Step 3a: 要約ファイルの作成

#### ファイル種別

| 種別 | 出力先 | テンプレート |
|------|--------|-------------|
| 大会概要 | `docs/{event-slug}-summary.md` | [template.md](template.md) |
| レギュレーション | `docs/{event-slug}-regulation-summary.md` | [regulation-template.md](regulation-template.md) |

#### レギュレーション要約の追加ルール

- **事実のみ**。AI の解説・示唆・修正案は書かない
- `primary_source` に応募要項 URL を設定
- 重要項目に `出典` 列を付ける
- `verified: true` は Step 4 完了後のみ

#### 大会概要要約

- 「開発への示唆」は**任意**（一般アドバイスでありレギュレーションではない）
- レギュレーション詳細は regulation-summary へリンク

#### メタデータ

```yaml
---
primary_source: https://...   # 応募要項等
fetched_at: 2026-05-29
event_name: イベント名
verified: false
---
```

### Step 3b: プロジェクト構成の作成

[project-structure.md](project-structure.md) 参照。存在しないファイルのみ作成。

- `docs/demo-script.md` → **審査用デモ確認シート**（プレゼン台本と決め打ちしない）
- `docs/tasks.md` → **参加ラウンドのタイムテーブル**を応募要項から転記
- 審査方式が「プレゼン不要」なら、スライド・QR・Drive 関連タスクを入れない

### Step 4: 品質チェック

[verification.md](verification.md) の拡張チェックリストをすべて確認。

追加:

- [ ] 2025年等の**別年次**ルールが混ざっていない
- [ ] 「プレゼン」「Google Drive」「参加費」等は応募要項と一致
- [ ] 参加ラウンド以外の申込期間を記載していない
- [ ] レギュレーション要約に AI 独自セクションが無い

**1つでも未達 → `verified: false` のまま。ユーザーに確認を求める。**

## 原則

1. **正確性 > 完全性** — 不明な項目は空欄・未確認。推測で埋めない
2. **応募要項が正** — PDF・記憶・一般常識より優先
3. **年次・ラウンドを混ぜない** — 2026年3rd ≠ 2025年 ≠ 5thラウンド
4. **非破壊** — 既存ファイルは上書きしない（修正時は変更点を明示）
5. **検証可能** — `primary_source` と `出典` で追跡可能に
