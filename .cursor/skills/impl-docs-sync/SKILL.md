# 実装後ドキュメント同期

目的: **次のチャット／別エージェントが、コードを全部読まなくても現状を把握できること。**

計画ファイル（`.cursor/plans/*.plan.md`）は作業メモ。**正本は `docs/`**。計画だけ更新して終わりにするな。

## 必須タイミング

次のいずれかが終わったら、完了報告の **前** にこの skill を実行する。

- plan / 機能の実装（API・画面・ストア）
- エンドポイント・リクエスト／レスポンス形の追加・変更
- デモの操作手順が変わる UI
- 環境変数キーの追加（値は書かない）

微小な typo・コメントのみならスキップ可。迷ったら更新する。

## やらないこと

- Cloud Run などへの **デプロイ**（依頼があるまで）
- `.env` の実値、秘密、絶対パスを docs に書く
- MVP を超える機能を `docs/idea.md` に勝手に Must 化（余力なら「ある／任意」と明記）
- 計画ファイルのフロントマター（todos status）をユーザー禁止時に編集

## 手順（この順）

1. **差分を一言で要約する**（例: 「案件・タグ・再検索・お気に入り・メモ」）
2. 下表で **触るファイルを決める**（該当だけ。空更新しない）
3. 既存の節に追記・表を直す。長文の再発明はしない
4. 秘密・実 URL・鍵が混入していないか確認
5. 完了報告に「更新した docs パス」を列挙する

## 変更種別 → 更新先

| 実装したこと | 必ず見る | 追記内容の例 |
|--------------|----------|--------------|
| API 経路・JSON 形 | `docs/architecture.md` の API 表、必要なら `.cursor/rules/api_contract.mdc` | method / path / 用途 / セッション要否 |
| クラウド部品・データ境界・エージェント段 | `docs/architecture.md` | 節・表・mermaid（簡潔） |
| MVP に入る体験 | `docs/idea.md` | Must / 余力の1行。範囲を広げすぎない |
| 進捗・完了タスク | `docs/tasks.md` | 該当行を `[x]` または追記。詳細 sync は `hackathon-tasks-sync` |
| デモの見せ方が変わる | `docs/demo-script.md` | 操作順の差分だけ |
| 環境変数キー | `docs/deploy/env-contract.md`、必要なら `.env.example` | **キー名のみ** |
| 公開してよい識別子 | `docs/deploy/status.md` | 依頼・確定時のみ |

詳細のチェックリスト: [checklist.md](checklist.md)

## 書き方の約束

- 日本語。識別子・パスは英語のまま
- 絶対パス禁止（`naming` / `security` に合わせる）
- 「いま動くこと」と「後回し／未接続」を混ぜない
- セッション内だけの状態（お気に入り等）は **永続しない** と明記する

## 完了報告テンプレ

```text
ドキュメント同期:
- docs/architecture.md: …
- docs/tasks.md: …
（該当なしのファイルは書かない）
```

コード実装だけ報告して docs を省略したら、この skill 未実施とみなす。
