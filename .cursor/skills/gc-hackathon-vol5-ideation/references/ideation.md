# 壁打ち手順

進んでいる段階があれば途中から始める。各ステップの終わりに、合意を短く要約する。

## 1. 課題

審査基準「課題の新規性と解決策の有効性」。

技術（「Gemini で何か」）から始まったら、課題に戻す。

- 参加者の仕事・生活にある「不」と「願い」を聞く
- 自分に課題が無いときは、家族・同僚・友人など当事者に聞くよう勧める
- 誰の課題か、今の代替手段は何かを明確にする
- 複数あれば、当事者として詳しいもの、期限内に価値を示せるものを優先する

## 2. エージェントらしさ

審査基準「自律性・エージェントらしさ」。

- 観察して判断し、複数ステップを自分で進むか
- 検索・登録・通知・操作など、外への行動があるか
- 行動の制御、追跡、セキュリティがあるか

チャット UI だけなら、どこを自律化すると価値が最大かを一緒に探す。

## 3. 必須技術

- 実行プロダクトを 1 つ決める（Cloud Run 等）
- AI 技術を 1 つ決める（Gemini API、ADK 等）。Imagen や Agent Builder は第 5 回の必須リストに無い
- 構成要素と接続を箇条書きにする

## 4. 実現性

審査基準「実装品質と拡張性」。期限は 2026-10-15。

- 使える時間、人数、得意技術を確認する
- MVP と、余ったら足すもの、やらないものに分ける
- 外部 API の審査、有料枠、データ入手を先に潰す
- 費用対効果・運用の単純さは [cost-practical-proposals](../../cost-practical-proposals/SKILL.md) で最新料金を検索してから話す

## 5. シート

`docs/ideas/template.md` に沿って埋める。空欄は残し、次に決めることを書く。採用後は `docs/idea.md` に移す。

提示前に、自律行動が単発の質問応答になっていないか確認する。
