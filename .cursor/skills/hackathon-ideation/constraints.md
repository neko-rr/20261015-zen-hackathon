# 制約の収集

アイデア出し前に埋める項目。**推測で埋めない。** 不明は `{未確認}` またはユーザーに確認。

## 収集チェックリスト

```
制約収集:
- [ ] 開発時間（開始〜提出/審査）
- [ ] チーム人数・役割
- [ ] テーマ（原文）
- [ ] 成果物形式（Web / アプリ / 任意 等）
- [ ] 審査方式（操作 / プレゼン / 書類 等）
- [ ] 審査時間（1チームあたり）
- [ ] 提出物・提出期限

- [ ] 技術制限（言語・クラウド・API 等）
- [ ] 事前作り込みの可否
- [ ] 必須技術（AI 利用義務 等）
```

## 情報源の優先順位

| 優先 | ソース | 信頼条件 |
|------|--------|----------|
| 1 | ユーザーが貼った要項・テーマ原文 | そのまま正とする |
| 2 | `docs/*-regulation-summary.md` | `verified: true` または `primary_source` |
| 3 | `AGENTS.md` | ハッカソン制約セクション |
| 4 | `docs/tasks.md` | 当日タイムライン |
| 5 | `docs/ideas/comparison.md` | 議論ルール・確定技術 |
| 6 | `docs/idea.md` | **採用案確定後のみ**（開発の正） |
| 7 | `docs/ideas/*.md` | 候補の技術メモ（未確定） |

## フォルダとの関係

| フェーズ | 参照するファイル |
|----------|-----------------|
| 発散〜議論 | `docs/ideas/*.md`, `comparison.md` |

## 審査方式別のソフト制約

### 操作デモ型

- ログイン不要で核心機能を触れる
- サンプル入力を用意
- 3〜5分で操作完結
- **審査員がIT素人**の場合: 専門用語なし・初見1画面で目的が分かる・大きなボタン

### プレゼン型

- 動くデモを優先
- 話と画面を1:1対応

### 提出物が URL のみ

- デプロイ先を開発時間内に確定できる構成

## テーマ未確定時（prep）

- 想定ジャンル・得意技術を `comparison.md` にメモ可
- **MVP 確定・selected 付与は禁止**
