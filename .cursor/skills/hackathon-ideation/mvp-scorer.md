# MVP 実現性スコアリング

各アイデアを **5観点 × 3点 = 15点満点** で評価する。  
審査基準が doc にあれば、該当観点の重みを ×1.5 相当で考慮（説明に明記）。

## 採点表

| # | 観点 | 3点 | 2点 | 1点 | 0点 |
|---|------|-----|-----|-----|-----|
| A | **開発時間内に Must が完結** | 余裕あり | ギリギリ | 削れば可能 | 不可能 |
| B | **テーマ適合** | 直球で一致 | 間接的に一致 | 弱い関連 | 外れ |
| C | **審査で伝わる** | 操作/発表で即理解 | 説明が少し必要 | 分かりにくい | 見せられない |
| D | **動くプロダクト** | 1機能が確実に動く | デモデータで動く | 部分のみ | アイdeaのみ |
| E | **技術リスク** | 既知スタックのみ | 1点未知 | 複数未知 | 当日初見の技術 |

**推奨閾値:** 合計 **9点未満は採用しない**（プロジェクトで変更可）

## 審査基準との対応（重み調整）

regulation-summary や要項に審査基準がある場合:

| 要項のキーワード | 強化する観点 |
|-----------------|-------------|
| 実装度・動くこと | D |
| テーマ適合 | B |
| AI 活用度 | C（AI の見え方）+ E（API 安定性） |
| 独創性・チャレンジ | B + E（ただし A を下げない） |
| UX / デザイン | C |

**ルール:** A（時間内完結）を **2点未満にする案は、他が満点でも推奨しない。**

## リスク早見表（E の判定用）

| 要素 | リスク |
|------|--------|
| ユーザー認証・OAuth | 高 |
| リアルタイム同期 | 高 |
| 外部 API 3つ以上 | 中〜高 |
| 初めてのクラウドサービス | 高 |
| LLM 1 API + 単一画面 | 低〜中 |
| 静的フロント + 既存 BaaS | 低 |

## タイムボックス超過時

議論が上限を超えたら:

1. 上位3案のうち **A が最大** の案を推奨
2. Nice を全削除した縮小版を提示
3. 「今日中に URL / デモが出る案」を最優先
