# 検索クエリ設計

競合分析の **Step 2** 用。1クエリ = 1回の `WebSearch`。

## スコープチェックリスト

```
- [ ] 核心機能（1つ）が言語化されている
- [ ] ターゲットユーザーが分かる
- [ ] 直接競合 vs 間接競合の境界
- [ ] 地理（日本のみ / グローバル）
- [ ] 時間上限（分）
```

## クエリテンプレート

### 製品・サービス発見

```
{キーワード} app
{キーワード} サービス 日本
{キーワード} SaaS
{テーマ} AI {year}     # 例: diary AI 2026
```

### 機能特化

```
"{核心機能}" web application
{核心機能} generator online
{核心機能} API demo
```

### 日本語

```
{課題} 解決 アプリ
{課題} ツール おすすめ
{カテゴリ} 無料 Web
```

### 比較・代替

```
{既知競合A} alternative
{既知競合A} vs {既知競合B}
best {カテゴリ} tools
```

### オープンソース / デモ

```
{キーワード} github
{キーワード} open source
{キーワード} demo site:github.io
```

### ハッカソン・展示（参考）

```
{テーマ} hackathon project
{キーワード} demo day
```

## クエリ数の目安

| モード | 最小 | 推奨 |
|--------|------|------|
| focused | 4 | 6 |
| landscape | 6 | 10 |

## Fetch 優先ドメイン

| 優先 | 理由 |
|------|------|
| 公式サイト | 機能の正 |
| producthunt.com | プロダクト概要 |
| github.com | OSS・実装参考 |
| apps.apple.com / play.google.com | モバイル競合 |
| note.com / zenn.dev | 日本の個人開発事例 |

## 避けるクエリ

| 例 | 理由 |
|----|------|
| 曖昧な1語のみ `AI` | ノイズ过多 |
| ログイン必須 SaaS の内部機能 | 検証不能 |
| 有料レポート PDF | Fetch 不可が多い |

## 検索後の整理

各ヒットを分類:

| 分類 | 定義 |
|------|------|
| **直接** | 同じ核心体験 |
| **間接** | 同じ課題・別手段 |
| **参考** | UI/技術の参考のみ |
| **除外** | スコープ外 |

直接競合は **focused で最大 5 件** に絞る。
