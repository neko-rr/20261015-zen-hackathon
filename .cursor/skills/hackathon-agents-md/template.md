## 開発方針

- **MVP 優先**: デモで見せる1フローに絞る
- **縦スライス**: UI → API → AI の最小経路を先に通す
- **新規導入**: チームが既知の技術を優先。初見の FW は避ける
- **エラー処理**: デモパスのみ。エッジケースは後回し
- **UI**: 見た目より操作の確実性。デモで失敗しない経路を確保

- 1ファイル1責務。200行超えたら分割を検討

## AI エージェント向け指示

### やること

- 変更前に `docs/idea.md` の MVP スコープを確認
- 小さな差分で提案。1タスク = 1機能
- デモ経路が動くことを最優先
- 外部 API 呼び出しは try-catch とタイムアウト

### やらないこと

- API キー・`.env` の値をコードやログに出力
- 大規模リファクタ・ディレクトリ再編（提案のみ）
- デモに不要な機能追加（「ついでに」禁止）
- `node_modules/` 等の自動生成物を手編集
- レギュレーション違反（事前開発、テンプレ流用等）

### 判断に迷ったら

1. デモで見せられるか？
2. 3時間（または残り時間）で終わるか？
3. チームの既知スタックか？
