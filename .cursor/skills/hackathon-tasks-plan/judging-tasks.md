# 審査方式別・横断タスク

regulation-summary または AGENTS.md から **審査方式を判定** し、P0 横断タスクを追加する。  
判定不能は `{未確認}` とし、ユーザーに確認。

## 審査方式の判定

| キーワード（要約・要項） | 方式 ID |
|-------------------------|---------|
| 審査員が操作、デモ、体験、触る | `demo` |
| プレゼン、登壇、発表、スライド | `presentation` |
| URL / リポジトリ提出のみ（審査詳細なし） | `submit` |
| 操作 + プレゼン両方 | `hybrid` |

**複数該当:** regulation-summary を正とする。

## 共通 P0（全方式）

| タスク | 備考 |
|--------|------|
| 採用案 Must の機能分解 | idea.md ベース |
| 提出形式に合った成果物 | Web / ビルド成果物等 |
| デプロイ or 提出準備 | **AGENTS.md コマンド** → `infra/`（あれば） |
| 審査用サンプルデータ / 入力例 | 審査員・観客がそのまま試せる |
| `docs/demo-script.md` 更新 | 方式に合わせた手順 |

## 方式別 P0 追加

### `demo`（操作デモ）

| タスク | 備考 |
|--------|------|
| 指定ブラウザ・環境での動作確認 | 要項のブラウザ名（例: Chrome）があればそれ |
| ログイン不要で核心機能 | 当日アカウント作成は避ける |
| 審査時間内の操作フロー確認 | 要項の分数（例: 3分）に合わせる |
| IT素人向け UI 確認 | AGENTS.md に記載があれば: 専門用語なし・サンプル入力・大きな CTA |

### `presentation`（プレゼン）

| タスク | 備考 |
|--------|------|
| 発表時間内のデモ/Rehearsal | 要項の分数に合わせる |
| 話す内容と画面の対応 | demo-script に台本 |
| デモ失敗時のバックアップ | スクショ / 録画 / 簡易版 |

### `submit`（提出のみ）

| タスク | 備考 |
|--------|------|
| 提出先・期限の確認 | 要項どおり |
| README / 提出メモ | 必要なら |

### `hybrid`

`demo` + `presentation` の P0 を **両方** 含める（時間が足りなければ demo 優先）。

## 成果物形式別メモ

| 形式 | デプロイ P0 の例 |
|------|-----------------|
| Web + URL 提出 | 公開 URL 確定、HTTPS |
| リポジトリ提出 | push 完了、README |
| 実行ファイル | ビルド成果物、起動手順 |
| 任意 | AGENTS.md / idea.md のインフラ記載に従う |

## 品質チェック（審査方式）

- [ ] 方式 ID を tasks.md に1行記載（例: `審査方式: demo`）
- [ ] 横断 P0 が方式と矛盾していない
- [ ] プレゼン不要の大会にスライド作成 P0 がない
- [ ] 操作デモなのにログイン必須 MVP になっていない
